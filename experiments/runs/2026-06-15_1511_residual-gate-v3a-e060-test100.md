## Purpose

Close the open loop on `residual_gate_v3a`: it was trained to epoch 60 on
2026-06-13 (`DONE in 30908.1s`, 12 checkpoints) but never evaluated. This run
evaluates the v3a gate against the frozen U-Net baseline and the v1 gate on the
same val20 and full test100 splits.

v3a is the v1 reliability gate with three extra input channels recommended by
the v1 calibration analysis (`2026-06-11_1615_residual-gate-v1-test100-calibration.md`):
`heart_mask`, `boundary_band`, and `residual_snr = |mu_r| / sigma_r`
(9 channels total vs v1's 6). Loss and `g_max=0.25` are unchanged from v1.

```text
corrupted CT -> frozen U-Net -> posterior residual diffusion -> learned reliability gate (v3a, 9ch)
```

## Intent (falsifiable)

The extra structure/reliability channels should let the gate release more
correction precisely where the v1 calibration showed the signal lives
(heart + boundary), so the **expectation** is:

- v3a heart MAE delta and boundary MAE delta on test100 are **better** than v1's
  (v1: heart -0.6535 HU, boundary -0.7219 HU), while global MAE delta is no worse
  than v1's -0.0762 HU.

**Falsification:** if v3a's heart/boundary deltas are not better than v1's within
run-to-run noise (or global MAE delta regresses), the extra channels do not help
at this training budget -> v3a is a TIE/DISCARD and v1 remains the anchor. A
2-case val smoke already showed v3a global delta -0.072 HU (heart -0.54,
boundary -0.68), i.e. comparable to v1, so the result is not pre-determined.

## What happened

v3a is a valid, consistent refinement (100/100 cases improved, like v1) but it
**does not beat v1**. On the two primary correction metrics it is a tie-to-slightly-worse:
global MAE Δ -0.0662 vs v1 -0.0762 (difference 0.010 HU, well within the ~0.015 HU
per-run noise), and heart MAE Δ -0.5624 vs v1 -0.6535 (v3a consistently ~0.09 HU
*less* improvement). Boundary MAE is a tie. The only place v3a clearly wins is
**boundary-gradient L1** (-0.327 vs v1 -0.228), i.e. the extra structure channels
push the gate slightly more toward edges — but not enough to help heart/global MAE.

This **falsifies the stated intent**: the three structure/reliability channels
(`heart_mask`, `boundary_band`, `residual_snr`) were expected to let the gate
release *more* correction in heart/boundary and beat v1 there. Instead the gate
became marginally more conservative (lower gate mean) and heart MAE regressed
slightly. At this training budget (same 60 epochs, same conservative v1 loss, same
small train100 cache), the added inputs do not translate into better correction —
plausibly because the loss never rewards using them and the gate has no signal to
exploit `residual_snr`/masks beyond what the 6 v1 channels already encode.

## Decision

**DISCARD v3a as a replacement.** `residual_gate_v1/train100_e060/epoch_060.pt`
remains the anchor / current best gated checkpoint. v3a is not promoted.

Caveat (not a reason to keep v3a as-is): the boundary-gradient edge is real and
suggests the structure channels *do* change gate behavior at edges. The right
follow-up is **not** "add more inputs" but to give the gate a reason to use them —
i.e. v3b = v3a inputs + a *weak, sparse, high-confidence* oracle auxiliary loss
(as proposed in the v1 calibration card), rather than the conservative-only v1 loss.

This is exactly why we closed the loop first: v3a had been trained but unevaluated,
and the intuitive assumption that "more reliability channels → better" turned out
to be false. Next-step planning should treat v1 as the best result, not v3a.
